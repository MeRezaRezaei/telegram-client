# Phase 2: TlIngest — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Groups in label order; same-group tasks touch disjoint files and MAY run parallel.

**Goal:** Ingest teleproto raw update arrays into the P1 Postgres truth (anchor/instance/child/route, tenant-scoped), idempotently, with entity aggregation (users/chats/channels become addressable rows) and Laravel events out — the writer P1 never had.

**Architecture:** `UpdateIngestor` walks any decoded TL payload recursively (constructor name under `_`, fields per P1 metamodel), upserting anchor→instance→children inside a DB transaction, with `route` idempotency for method responses and `tl_id`-aggregation for referenced entities. Pure transform + storage; no fetching, no handler logic (roadmap contracts).

**Tech Stack:** PHP 8.2+, teleproto, illuminate/database (Eloquent), PHPUnit + Orchestra Testbench (PG via in-memory SQLite where type-compatible; PG-only features — deferrable FKs, uuid — need the real PG in CI, locally SQLite for logic tests).

**Spec:** roadmap P2 + contracts (`docs/superpowers/specs/2026-08-28-master-roadmap.md`).

## Global Constraints

- Zero `preg_`, strict_types, MIT, arrays-in (teleproto truth) / models+events-out.
- Tenancy: every anchor row carries `account_id`; ingest API requires it (no global mode).
- No network in tests; canned wire payloads only.
- Generated layer (P1) is read-only for ingest — bugs found there get generator fixes + regenerate, never hand-edits.
- Gates per task: phpunit green, phpstan [OK].
