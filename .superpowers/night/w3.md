## Generator fix (regen, not hand-edit)

The single 999999 FK migration (1535 `ALTER TABLE … ADD CONSTRAINT … DEFERRABLE INITIALLY DEFERRED` in one transaction) exhausted stock PG's shared lock budget — `SQLSTATE 53200 out of shared memory, max_locks_per_transaction` (64 × 150 conns = 9600 slots; the ALTERs plus 3678 tables chain far past it). **Fix in `MigrationGenerator`: FK_BUCKET_SIZE = 512 — FK files are now bucketed** (`2026_08_28_99990{1,2,3}_add_tl_foreign_keys.php`), keeping each migration transaction inside stock-PG lock budget with no server tuning. Regenerated via `php bin/regenerate`; diff surgical (manifest sha256 pin unchanged — filenames/counts not in manifest; golden determinism test green). `MigrationGeneratorTest` updated + new bucket-bound assertion.

Second lock lesson (test-infra, not generator): teardown `DROP SCHEMA … CASCADE` over 3.7k tables blows the same budget, and unqualified `DROP TABLE IF EXISTS` names silently no-op off search_path — teardown drops FKs in batches of 200, then schema-qualified table batches of 256, then the schema.
