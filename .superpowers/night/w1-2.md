# Night W1-2 — Duplicate-anchor guard (P2 M3)

Repo: telegram-client @ bc31d27 (master). Carried P2 M3: `UpdateIngestor`
identity resolution can mint duplicate anchors for the same telegram
identity under concurrent workers — identity values live in per-constructor
instance tables, so no anchor-side DB unique constraint can guard the mint.

## Fix (TDD)

- `src/Ingest/IdentityLock.php` (new): constructor-free static
  collaborator. `acquire(Connection $c, string $key): void` —
  - in-process: static depth-counted key map; PHP workers are
    single-threaded, so the map exists to make nested (reentrant)
    acquires of the same key legal — documented choice, no blocking;
  - cross-worker: `select pg_advisory_xact_lock(hashtext(?))` via raw
    SQL on the caller's connection INSIDE the caller's transaction
    (xact-scoped: auto-releases at commit/rollback, nothing to forget;
    advisory locks are session-reentrant so nested acquires are safe).
    sqlite/mysql: documented no-op.
  - `release(string $key)` drops one depth level (pg needs no release).
- `src/Ingest/UpdateIngestor.php`: identity resolution + anchor
  mint/reuse + instance upsert wrapped in acquire/try/finally under key
  `tl_anchor:{accountId}:{identityColumn}:{naturalId}`; content
  aggregation is untouched (not the identity race).
