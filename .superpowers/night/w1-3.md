# W1-3 — Backup chunk GC (`telegram-client:backup prune`) (P4-carried M)

Repo: telegram-client @ 3a2e14a (after W1-1/W1-2 landed). Baseline 301 tests
→ 319 green (5 live-gated skips), phpstan L5 + disallowed-calls [OK], zero
`preg_` in src/. Committed as `feat(backup): prune orphans — chunk GC (P4 carried)`.

## Problem

Files deleted between backup runs drop their chunks out of the new manifest's
file lists, but nothing ever removed them from the vault channel: a shrinking
set never shrank its channel (docs/backup.md "No garbage collection" limit).

## Fix

- `src/Backup/Pruner.php` — `Pruner::prune(VaultInterface, array $keepHashes):
  array{scanned, pruned}`. Walks `findMessagesByName('')` (list-all), deletes
  every entry whose name is chunk-shaped — exactly 64 lowercase hex chars via
  `strlen` + `strspn`, no regex — and outside the keep-set. Non-string
  keepHashes entries (raw manifest data) ignored. Idempotent by construction.
- `VaultInterface` grew two methods (breaking for implementors; both in-repo
  impls + all test doubles updated):
  - `findMessagesByName(string $namePrefix): array` — prefix list; EMPTY
    prefix lists everything. TelegramVault backs it with the existing
    search+history merge; `messages.search` with empty q returns all messages
    per the Telegram docs (noted in the interface + TelegramVault docblocks).
  - `delete(string $name): void` — idempotent exact-name delete.
- `TelegramVault` — public `findMessagesByName`/`delete` (private static
  renamed `searchMessagesByName` to free the name); new `deleteMessages` api
  key via `UserAccountScope::deleteMessages($ids, revoke=true)`; entries
  surfaced as `{id: string, name: string}`.
- `InMemoryVault` — restructured to a flat message stack (chunk docs named by
  hash + `TBMANIFEST1:`-named manifest texts) so list/delete mirror the
  channel vault; chunk latest-write-wins and manifest-latest-wins preserved.
- `BackupCommand` — `prune` action: latest manifest → `chunk_hashes` keep-set
  → `Pruner::prune`; prints `prune set=<id> {scanned:N, pruned:M}`; keyless;
  fails loud (`prune needs a manifest first (run).`) when no manifest.
- `docs/backup.md` — CLI + new "Pruner semantics" section (incl. don't-prune-
  mid-run note: keep-set is the LATEST manifest); Limits rewritten: GC exists,
  manual.
